# 🪑 Motia Furniture CRM

Багатокористувацька CRM-система для управління меблевим виробництвом та проєктами, побудована на базі **Streamlit Cloud** із використанням екосистеми **Google Workspace** (Google Sheets як головна реляційна база даних та Google Drive як структуроване сховище проєктної документації).

---

## 🏗 Архітектура та ключові принципи

1. **Serverless & No-Cost Infrastructure:** Як бекенд використовуються захищені таблиці Google Sheets і Google Drive, що гарантує миттєвий доступ, спільну роботу команди та відсутність витрат на оренду класичних серверних баз даних.
2. **Багатокористувацькість (Multi-tenancy):** Централізований конфігураційний аркуш `Master_Config` дозволяє підключати нових партнерів або напрямки, розмежовуючи їхні персональні бази даних та кореневі папки на Диску.
3. **Рольова модель (RBAC):** Розподіл прав доступу на рівні адміністратора (повний огляд та управління всіма базами) та користувачів/менеджерів (доступ виключно до закріплених напрямків).
4. **Автоматизація через Google Apps Script:** Еталонні шаблони та процедури синхронізації (`syncAllDatabasesWithMaster`) автоматично оновлюють структуру робочих баз відповідно до єдиного корпоративного стандарту.

## 🔄 Логіка взаємозв'язку між модулями (Архітектурний потік)

1. **Ініціалізація та вхід (`app.py` ➔ `auth_service.py`):**
* При відкритті додатку `app.py` перевіряє наявність активної сесії користувача через нативну авторизацію Streamlit (`st.user.is_logged_in`).
* Після успішного входу через Google-акаунт пошта користувача передається в `auth_service.py`, яка звертається до центрального `Master_Config` і повертає профіль (роль та словник доступних баз даних з їхніми ID та ID папок на Диску).


2. **Маршрутизація (`app.py` ➔ `views/`):**
* На основі обраної у сайдбарі бази даних та розділу навігації `app.py` підключає відповідний в'ю (`manager_orders`, `new_order`, `dates_manager` тощо).


3. **Обробка даних замовлення (`views/new_order.py` ➔ `sheets_service.py` & `drive_service.py`):**
* Коли користувач створює нове замовлення через `new_order.py`, модуль залучає `sheets_service.py` для отримання списку контактів, генерації унікального ID (`ORD-YYYY-XXX`) та `drive_service.py` для сканування ієрархії папок на Google Диску (`Країна` ➔ `Місто` ➔ `Об'єкт`) або створення нових папок (якщо обрано варіант «Інше»).
* Після валідації дані записуються в таблицю `Orders`, а створена папка замовлення з набором стандартних підпапок (`Дизайн`, `Конструктив`, `Фінанси`, `Інше`, `Фотозвіт`) автоматично зв'язується з проєктом.

## 📄 Детальний опис компонентів і файлів

### 1. Головні файли та конфігурація

* **`app.py`**: Головний оркестратор додатку. Керує життєвим циклом сесії, ініціацією `st.login()`, відображенням панелі користувача у сайдбарі, вибором активного напрямку та динамічним роутингом інтерфейсу.
* **`requirements.txt`**: Список пакетів Python, необхідних для роботи застосунку:
```text
streamlit>=1.42.0
Authlib
httpx
gspread
google-api-python-client
google-auth
pandas

```


* **`.streamlit/secrets.toml`**: Захищене сховище ключів (дані сервісного акаунта Google, параметри OAuth та ідентифікатори master-таблиць).

### 2. Сервісні модулі (`utils/`)

* **`auth_service.py`**: Зчитує налаштування доступу з `Master_Config`, кешує результати та мапить пошту користувача до конкретних баз даних і директорій на Google Диску.
* **`sheets_service.py`**: Надає оптимізовані інструменти на базі `gspread` (з декоратором `@st.cache_resource` для клієнта). Здійснює зчитування таблиць у DataFrame (`get_orders_data`), фільтрацію довідника контактів (`get_contacts_list`), генерацію порядкових ID (`generate_next_order_id`) та збереження нових рядків (`save_new_order`).
* **`drive_service.py`**: Керує взаємодією з Google Drive API (використовуючи authenticated http-сесію сервісного акаунта). Реалізує рекурсивне сканування ієрархії папок (`get_drive_hierarchy`), пошук або створення папок за назвою (`ensure_folder`) та генерацію повного комплекту робочих підпапок для кожного замовлення.
* **`logger_service.py`**: Відповідає за формування стандартизованих рядків аудиту для відстеження історичних змін у проєктах.

### 3. Модулі інтерфейсу (`views/`)

* **`new_order.py`**: Інтерактивна форма створення замовлення. Забезпечує динамічне завантаження списку замовників із `Contacts`, вибір географічної ієрархії (Країна/Місто/Об'єкт) із підтримкою динамічного створення нових гілок через опцію «Інше», а також прив'язку відповідальних осіб (замірник, дизайнер, конструктор, монтажник).
* **`manager_orders.py`**: Робочий інтерфейс управління повним циклом виробництва та монтажу меблів (перегляд таблиці, оновлення статусів конвеєра).
* **`admin_dashboard.py`**: Інструменти моніторингу та адміністрування для керування доступом.
* **`client_portal.py`**: Полегшений інтерфейс для зовнішніх спостерігачів або замовників.
* **`dates_manager.py`**: Модуль календарного планування та контролю дедлайнів на основі аркуша `Dates_Log`.

## 🗄 Структура даних у Google Sheets

Кожна робоча база складається з трьох ключових синхронізованих аркушів:

1. **`Orders`**: Основна таблиця виробничого циклу (~40 колонок), що містить реквізити замовлення, статус архівування, часові мітки, фінансові нотатки, розподіл ролей та незалежні статуси для 8 етапів конвеєра.
2. **`Contacts`**: Централізований довідник осіб та організацій із гнучкими текстовими ролями через кому.
3. **`Dates_Log`**: Журнал подій, планових дедлайнів та історичних дат, прив'язаних до `ID Замовлення`.
