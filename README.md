# 🪑 Motia Furniture CRM

Багатокористувацька CRM-система для управління меблевим виробництвом та проєктами, побудована на базі **Streamlit Cloud** із використанням екосистеми **Google Workspace** (Google Sheets як головна база даних та Google Drive як сховище проєктної документації).

---

## 🏗 Архітектура та ключові принципи

1. **Serverless & No-Cost Infrastructure:** Як бекенд використовуються захищені таблиці Google Sheets, що забезпечує миттєвий доступ, спільну роботу та відсутність витрат на класичні серверні БД.
2. **Багатокористувацькість (Multi-tenancy):** Централізований конфігураційний аркуш `Master_Config` дозволяє підключати нових партнерів/напрямки, розмежовуючи їхні бази даних та папки на Диску.
3. **Рольова модель (RBAC):** Розподіл прав на рівні адміністратора (повний доступ до всіх баз) та користувачів/партнерів (доступ лише до призначених напрямків).
4. **Аудит та логування:** Відстеження змін за принципом delta-updates (`Історія змін замовлення`), а також гнучкий облік дедлайнів (`Dates_Log`).
5. **Автоматизація на Google Apps Script:** Еталонні шаблони та процедури синхронізації (`syncAllDatabasesWithMaster`) автоматично оновлюють структуру робочих баз відповідно до корпоративного стандарту.

## 📁 Структура проєкту

```text
furniture-crm/
│
├── app.py                      # Головна точка входу (роутинг, ініціалізація сесії, авторизація)
├── requirements.txt            # Залежності проєкту (streamlit>=1.42.0, gspread, pandas тощо)
├── .streamlit/
│   └── secrets.toml            # Секрети (Master ID, OAuth, Service Account)
│
├── utils/                      # Сервісні модулі
│   ├── auth_service.py         # Логіка автентифікації та перевірки ролей через Master_Config
│   ├── sheets_service.py       # Робота з gspread (читання, кешування, оновлення рядків)
│   ├── drive_service.py        # Автоматичне створення папок і підпапок на Google Диску
│   └── logger_service.py       # Формування історій змін (хто, коли, що змінив)
│
└── views/                      # Логіка екранів інтерфейсу
    ├── admin_dashboard.py      # Зведена аналітика та селектор баз для адміністратора
    ├── manager_orders.py       # Повний інтерфейс для менеджерів (усі колонки конвеєра)
    ├── client_portal.py        # Полегшена форма для клієнтів (обмежений вигляд)
    └── dates_manager.py        # Модуль управління датами та дедлайнами з гнучкими коментарями


    📄 Детальний опис компонентів і файлів
1. Головні файли та конфігурація
app.py: Головна точка входу в додаток. Реалізує нативну авторизацію Streamlit через Google (st.login / st.user), перевіряє права доступу користувача в Master_Config, керує вибором активного напрямку (якщо їх кілька) та відповідає за загальну навігацію бічного сайдбару.

requirements.txt: Містить перелік необхідних бібліотек Python (streamlit, gspread, google-api-python-client, pandas тощо).

.streamlit/secrets.toml: Локальний або облачний файл конфігурації з конфіденційними даними (ID головного Master-реєстру, облікові дані сервісного акаунта Google, параметри OAuth).

2. Сервісні модулі (utils/)
auth_service.py: Відповідає за зчитування Master_Config, кешування конфігурації та функцію authenticate_user. Зіставляє пошту користувача з базою та формує словник доступних баз даних (sheet_id та drive_folder_id).

sheets_service.py: Інкапсулює взаємодію з бібліотекою gspread. Забезпечує безпечне читання даних із таблиць Google Sheets, їх перетворення у DataFrame та оновлення статусів/рядків.

drive_service.py: Керує інтеграцією з Google Drive API. При створенні нового замовлення автоматично генерує ієрархію папок на Диску (головна папка замовлення всередині папки напрямку + обов'язкові підпапки: Дизайн, Конструктив, Фінанси, Інше, Фотозвіт).

logger_service.py: Формує стандартизовані рядки аудиту ([Дата/Час | Email | Що саме змінено]) для запису в колонку «Історія змін замовлення».

3. Модулі інтерфейсу (views/)
manager_orders.py: Основний робочий простір менеджера або виробничника. Відображає таблицю конвеєра замовлень, дозволяє редагувати етапи, керувати статусами та коментарями.

admin_dashboard.py: Інтерфейс для адміністраторів системи. Надає інструменти моніторингу, керування доступом та управління синхронізацією баз.

client_portal.py: Спрощений та обмежений інтерфейс для клієнтів або зовнішніх замовників (бачення статусу проєкту без технічних деталей виробництва).

dates_manager.py: Модуль управління дедлайнами, плановими та фактичними датами подій, пов'язаними з конкретними ID замовлень (працює в зв'язці з аркушем Dates_Log).

🗄 Структура даних у Google Sheets
Кожна робоча база складається з трьох ключових аркушів, які синхронізуються за допомогою еталонного шаблону:

Orders: Головна таблиця замовлень (~40 колонок), що містить реквізити клієнта, фінансові коментарі, розподіл відповідальних осіб (замірник, дизайнер, конструктор, монтажник тощо) та 8 конвеєрних етапів із незалежними статусами.

Contacts: Єдиний довідник клієнтів, партнерів, підрядників та робітників із підтримкою гнучких текстових ролей та контактних даних.

Dates_Log: Журнал дат, подій та дедлайнів для гнучкого календарного планування кожного проєкту.
