# 🪑 Motia Furniture CRM

Багатокористувацька CRM-система для управління меблевим виробництвом та проєктами, побудована на базі **Streamlit Cloud** із використанням екосистеми **Google Workspace** (Google Sheets як реляційна база даних та Google Drive як структуроване сховище проєктної документації).

---

## 🏗 Архітектура та ключові принципи

1. **Serverless & No-Cost Infrastructure:** Як бекенд використовуються захищені таблиці Google Sheets і Google Drive, що гарантує миттєвий доступ, спільну роботу команди та відсутність витрат на оренду серверних баз даних.
2. **Багатокористувацькість (Multi-tenancy):** Централізований конфігураційний аркуш `Master_Config` дозволяє підключати нових партнерів чи напрямки, розмежовуючи їхні персональні бази даних (`sheet_id`) та кореневі папки на Диску (`drive_folder_id`).
3. **Рольова модель (RBAC):** Розподіл прав доступу на рівні адміністратора (`role == "admin"`, який має повний доступ до всіх баз напрямків у `Master_Config`) та користувачів/менеджерів (`role == "user"`, які бачать виключно власні закріплені бази).
4. **Автоматизація через Google Apps Script:** Еталонні шаблони та процедура синхронізації (`syncAllDatabasesWithMaster`) в окремому автономному скрипті оновлюють структуру робочих баз відповідно до єдиного корпоративного стандарту.

## 📄 Детальна логіка функцій та файлів

### 1. Головна точка входу: `app.py`

Файл є центральним оркестратором додатку:

* **Перевірка авторизації (`st.user.is_logged_in`):** Якщо користувач не увійшов, відображається підказка та кнопка `st.login()`, після чого виконання зупиняється (`st.stop()`).
* **Автентифікація профілю:** Отримує `google_email` (`st.user.email`) і звертається до `authenticate_user(google_email)` у `auth_service.py`. Якщо користувача не знайдено або акаунт відсутній у конфігурації — виводить помилку доступу та кнопку `st.logout()`.
* **Формування Сайдбару:** Відображає ім'я, пошту, роль та кнопку виходу. Якщо у користувача декілька баз — рендерить `st.sidebar.selectbox` для вибору активного напрямку.
* **Отримання ідентифікаторів баз:** На основі вибору `selected_db_name` витягуються параметри з об'єкта `profile['available_databases'][selected_db_name]`:
* `selected_sheet_id` — ID Google Таблиці замовлень.
* `drive_folder_id` — ID кореневої папки напрямку на Google Диску.


* **Маршрутизація:**
* `"📋 Актуальні замовлення"` ➔ викликає `get_orders_data(selected_sheet_id, "Orders")` і відображає таблицю через `st.dataframe()`.
* `"➕ Нове замовлення"` ➔ передає `selected_sheet_id` та `drive_folder_id` у `render_new_order_view()`.
* `"👥 Контакти"` ➔ викликає повноцінний інтерфейс `render_contacts_view(selected_sheet_id)`.

### 2. Сервісні модулі (`utils/`)

#### 🛠 `utils/auth_service.py`

Модуль відповідає за перевірку доступу та логіку авторизації:

* `@st.cache_data(ttl=300) get_master_config() -> pd.DataFrame`:
Отримує `MASTER_SHEET_ID` із секретів `st.secrets`. Через `get_orders_data` зчитує конфігураційну таблицю `Master_Config` і кешує її у вигляді DataFrame на 5 хвилин для прискорення роботи додатку.
* `authenticate_user(email: str) -> dict | None`:
1. Нормалізує значення в колонці `Email користувача` (приведення до нижнього регістру, вилучення пробілів).
2. Шукає користувача за вказаним `email`. Якщо рядок відсутній — повертає `None`.
3. Визначає роль користувача (`role = "admin"` чи `"user"`).
4. Фільтрує записи з наявним та валідним `ID бази даних`.
5. Формує словник `available_databases`:
* Якщо **`role == "admin"`**: додає всі валідні напрямки з `Master_Config`.
* Якщо **`role == "user"`**: додає лише ті напрямки, які безпосередньо прив'язані до даної пошти.


6. Структура елемента `available_databases[db_name]`:
```python
{
    "sheet_id": "...",
    "drive_folder_id": "..."
}

```


7. Повертає словник профілю: `{"user_id": ..., "email": ..., "name": ..., "role": ..., "available_databases": ...}`.



#### 🛠 `utils/sheets_service.py`

Модуль інкапсулює роботу з Google Sheets API через `gspread`:

* `@st.cache_resource get_gspread_client()`:
Ініціалізує та кешує з'єднання клієнта `gspread` за допомогою ключів сервісного акаунта з `st.secrets["gcp_service_account"]`.
* `get_orders_data(spreadsheet_id: str, sheet_name: str = "Orders") -> list[dict]`:
Відкриває таблицю за `spreadsheet_id`, зчитує всі записи аркуша `sheet_name` та повертає їх у вигляді списку словників.
* `@st.cache_data(ttl=30) get_all_contacts_records(spreadsheet_id: str) -> list`:
Зчитує всі записи з аркуша `Contacts` та кешує їх на 30 секунд.
* `generate_next_order_id(spreadsheet_id: str) -> str`:
Зчитує 1-шу колонку аркуша `Orders`, фільтрує існуючі ідентифікатори поточного року (напр., `ORD-2026-XXX`), знаходить максимальний порядковий номер і ґенерує наступний ID (наприклад, `ORD-2026-004`).
* `save_new_order(spreadsheet_id: str, order_data: dict) -> str`:
Створює новий `ID Замовлення`, ставить мітки `Час створення` та `Час останнього редагування`, порівнює передані дані із заголовками шапки `Orders` і додає рядок у таблицю за допомогою `append_row()`.
* `save_new_contact(spreadsheet_id: str, contact_data: dict) -> bool`:
Універсальна функція роботи з контактами:
* **Створення:** Якщо `ID Контакту` відсутній, генерує наступний ідентифікатор у форматі `CONT-XXX` та додає новий рядок у таблицю `Contacts`.
* **Оновлення:** Якщо `ID Контакту` передано, знаходить відповідний рядок за ID у 1-й колонці та оновлює його дані за допомогою `worksheet.update()`.
* Автоматично очищує кеш контактів (`st.cache_data.clear()`).



#### 🛠 `utils/drive_service.py`

Модуль керує Google Drive API:

* `get_drive_service()`:
Створює екземпляр `googleapiclient.discovery.build("drive", "v3", ...)` на основі авторизації з `get_gspread_client()`.
* `list_subfolders(service, parent_id: str) -> list[dict]`:
Шукає не видалені підпапки усередині `parent_id`.
* `get_drive_hierarchy(root_folder_id: str) -> tuple[dict, dict]`:
Сканує 3-рівневу структуру папок у корені напрямку: **Країна ➔ Місто ➔ Об'єкт**. Повертає вкладений словник структури та мапінг `шлях -> folder_id`.
* `ensure_folder(service, parent_id: str, folder_name: str) -> str`:
Перевіряє наявність папки `folder_name` у `parent_id`. Створює її, якщо відсутня, та повертає `id`.
* `create_order_folder_structure(root_folder_id, country, city, object_name, order_folder_name) -> str`:
Створює ієрархію папок замовлення:
1. Знаходить/створює папку **Країни**.
2. Знаходить/створює папку **Міста**.
3. Знаходить/створює папку **Об'єкта**.
4. Створює **папку замовлення** всередині об'єкта.
5. Створює 5 стандартних підпапок (`Дизайн`, `Конструктив`, `Фінанси`, `Інше`, `Фотозвіт`).
6. Повертає пряме веб-посилання (`webViewLink`) на створену папку замовлення.

### 3. Модулі інтерфейсу (`views/`)

#### 👥 `views/contacts_manager.py`

Центральний модуль для управління довідником контактів та інтеграції контактів у форму замовлення:

* **`render_role_picker(label, key_suffix, default_roles=None)`**:
Двоколоночний віджет для вибору кількох ролей із зумовленого списку `ALL_ROLES` (`Замовник`, `Замірник`, `Дизайнер`, `Конструктор`, `Виробник`, `Монтажник`, `Інше`) із можливістю швидкого видалення обраних ролей.
* **`render_contact_picker(label, key_suffix, role_filter="", selected_sheet_id=None, all_contacts_records=None)`**:
Інтерактивний компонент вибору контактів з бази для форми створення замовлення. Дозволяє фільтрувати за роллю та викликати інлайн-форму додавання нового контакту.
* **`render_contact_form(selected_sheet_id, default_role="", contact_data_to_edit=None, key_suffix="new_contact", on_success=None)`**:
Універсальна форма створення/редагування контакту:
* Збирає ПІБ, Компанію, Ролі, Телефони, Email, Telegram, Тип (Фіз./Юр.), Адресу та Коментар.
* У режимі редагування шукає та відображає зв'язані проєкти замовлень з аркуша `Orders`.
* Динамічно змінює назву кнопки (`"💾 Зберегти нові дані"` / `"🔄 Оновити контакт"`).
* Після збереження повертає інтерфейс до початкового стану.


* **`render_contacts_view(selected_sheet_id)`**:
Повноцінна сторінка довідника контактів:
* **Гнучкий пошук:** Комплексний пошук одночасно за кількома полями: **Ім'я**, **Компанія**, **Адреса** та **Коментар**.
* **Фільтрація:** Селектор фільтрації за роллю.
* **Табличний вигляд:** Компактна таблиця із колонками: **Ім'я** (`ПІБ / Назва` та `ID`), **Ролі**, **Телефони**, **Компанія** та **Кнопка редагування** (`use_container_width=True` з унікальними ключами для уникнення конфліктів Streamlit).



#### 🎨 `views/new_order.py`

* `render_new_order_view(selected_sheet_id: str, drive_folder_id: str)`:
Рендерить форму створення замовлення у Streamlit:
1. Отримує список контактів через `get_all_contacts_records()`.
2. Завантажує ієрархію папок з Диску через `get_drive_hierarchy()`.
3. Будує каскадні випадаючі списки `Країна` ➔ `Місто` ➔ `Назва об'єкта`. При виборі варіанту **«Інше»** активує поле текстового введення для нової папки.
4. Збирає дані відповідальних осіб (через `render_contact_picker`).
5. Після кліку на `st.form_submit_button`:
* Створює ієрархію папок на Диску через `create_order_folder_structure`.
* Зберігає новий рядок у Google Таблиці через `save_new_order`.
* Виводить повідомлення про успішне створення з прямою кнопкою-посиланням на папку на Диску.

## 🗄 Структура даних у Google Sheets

### 1. Центральна конфігурація: `Master_Config`

| Колонка | Опис |
| --- | --- |
| `User_ID` | Унікальний ідентифікатор користувача |
| `Ім'я / Напрямок` | Назва напрямку, філіалу або ім'я користувача |
| `Email користувача` | Google-пошта для авторизації в системі |
| `Роль` | Права доступу (`admin` або `user`) |
| `ID бази даних` | Ідентифікатор Google Таблиці даного напрямку |
| `ID папки Google Drive` | Ідентифікатор кореневої папки напрямку на Диску |
| `Коментар` | Службові примітки |

### 2. Структура робочих баз даних

Кожна робоча база містить 3 аркуші:

1. **`Orders`**: Основна таблиця виробничого циклу (~40 колонок), що містить реквізити замовлення, статус архівування, часові мітки, фінансові нотатки, розподіл ролей та незалежні статуси для 8 етапів конвеєра (`в роботі`, `перевіряються`, `готово` тощо).
2. **`Contacts`**: Довідник осіб та організацій із розширеними полями (`ID Контакту`, `ПІБ / Назва`, `Роль / Категорія`, `Телефон(и)`, `Email(и)`, `Нік Telegram`, `Компанія`, `Тип (Фіз./Юр.)`, `Адреса / Місто`, `Коментар`).
3. **`Dates_Log`**: Журнал подій, планових дедлайнів та фактичних дат, прив'язаних до `ID Замовлення`.
